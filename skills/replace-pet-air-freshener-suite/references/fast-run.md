# 集中决策与自主执行

用户已要求减少等待，把可以共同决定的问题合并；前30分钟集中决策，之后自主生成。每组以当批配置计算，12张只是本次计时参考；组数变化时重新估算。总目标90分钟包含人工回复、排队、修正与本地交付；用户另行明确要求代上传时才包含上传与云端核对，不能在资料就绪或审核通过后重新起算，也不能把人工等待从总耗时中扣除。此规则用于新任务及当前任务尚未完成的确认，不重开已完成步骤，不自动恢复其他聊天的任务。

## 启动确认单

先检查本轮已经提供且可读取的清单、目录和图片，填出已知内容；同一轮把影响当前任务的缺项集中询问。已明确的信息直接沿用，用户可只回复要补充或修改的项，不要求重填。确认单覆盖：

|事项|记录内容|
|---|---|
|清单与交付|Word/已明确清单、品种顺序、目标目录或网盘链接、产品后缀|
|原图|现成原图位置，或GPT制作；后者同时收集参考图、数量、款式、背景与文字|
|产品与模板|实际产品唯一结构来源、必要尺寸、各模块参考；本批是否沿用/更新固定模板，及更新映射|
|输出配置|场景数、人宠数、风格选择/首图/尺寸/品种选择y/n、是否统一全部组；选择页风格及实际页数|
|文字与分辨率|各产品姓名、其他受保护文字、Brittany Signature资源或视觉匹配限制；默认1254×1254，沿用用户固定选择，不再询问分辨率或放大|
|异常策略|检查发现的缺图、冲突和权限问题集中列出，由用户明确选择补齐、暂缓受影响项或其他具体方案|
|后续执行|首套通过后的品种范围、本地制作修改后同名保存最终版，由用户手动上传；依旧保留原图及独立素材，不增加默认ZIP|

不为未提供的信息编造答复；不为了填表新增与实际产品无关的问题。首次未拿到素材时，先收集素材位置及其他可回答项；拿到后完成可进行的全量检查，把新发现的问题汇总在下一份确认单，不逐文件逐问题打断。已经读取且哈希未变的素材与模板复用检查结果；新文件、变更文件和未核实内容仍需检查。新批次仍读取当前规则及模板版本，不盲用旧批缓存。

创建目录、原图检查、产品外观确认和配置确认仍应实际完成并分别记录状态，但可在同一轮完成、汇报和确认，不再各自要求用户回复。已有明确产品结构来源及必要规格且完成图片查看时，可登记产品外观已确认；有歧义则放入合并问题单。GPT制作原图仍须先查看用户本次参考、生成后确认可用，不以压缩轮次省去原图确认；其额外耗时计入总时间。

## 前30分钟的决策窗口

资料齐备、沿用可用模板时，以本次60张为试运行安排：0—8分钟完成资料检查及启动确认；8—20分钟完成首套；20—30分钟集中检查、收齐反馈并取得首套放行。首次启动、权限未通、新产品模板开发、GPT原图制作或大范围修改可能超过窗口，应及时报告实际缺项及预计影响，不能声称一定30分钟完成。

首套审核必须一次展示全部编号预览、已发现问题、限制及待决定事项。把以下事项合并到同一轮：

1. 本套整体是否通过；有修改则一次收齐各编号反馈，只修受影响项并复审。
2. 若启动时未明确锁定模板，在本次审核同时询问是否更新固定模板、来源和模块；已锁定且没有变更则不再问。
3. 通过后按已确认范围继续批量、自动检查，全部完成后核对本地成品并交付，由用户手动上传；已授权的执行范围不重问。

可提示用户用一句话答复，例如“整套通过，模板不更新，按已确认范围继续”，或“修改03和09，其余按确认单执行”。模板锁定、首套通过及批量范围须各有明确依据；单独认可某张不等于整套通过。仅“通过继续”且模板已锁定、范围已明确时即可放行，不再追加一个模板确认暂停。用户离开、30分钟到时或未回复不构成审核通过。

## 放行后的自主执行

- 已确认的配置、产品外观、尺寸、字体约定、模板版本、缺图处理、品种范围和上传方式不再重复询问。每组生成完立即做技术与视觉检查，问题在组内收敛，保留最终全批完整性核对。
- 漏字、串名、风格不符、尺寸线或产品外形不符合已确认要求时，按原要求修正；仅重做受影响图片。已明确授权且适用于本批的程序校正可复用；没有授权时不把上批局部修图许可扩大为所有图片的程序合成许可。遵守所用图像工具规则。
- 同一张图同类问题连续两次定向修复仍失败时，停止重复同一路径，保留成品和问题记录；采用已授权且适用的替代办法，否则将该项标为待处理，继续不受影响的已授权工作。不能为守时降质量或把失败项标成通过。
- 缺少新姓名、真实尺寸、未授权的产品/风格替代或交付权限等无法自行决定的问题，先核对现有记录；确需新答复时汇总待决定事项，不让单张或单组问题阻塞可独立完成的其余部分。首套未放行时仍不得启动剩余组。
- 新问题只影响一部分时，最终报告已完成/已上传/待处理的准确数量，未完成项不计交付完成。全批受到同一阻塞时立即汇总报告；不为凑满30或90分钟空等。
- 默认仅本地交付，由用户手动上传，不询问网盘目标或上传许可。只有用户另行明确要求代上传时才执行并回读核对。没有新增决定时直接交付结果，不制造额外暂停。邮件沿用主技能，只在确需用户处理的汇总节点发送，不按表格字段分别发送。

## 90分钟预算与计时

用户已再次明确：90分钟是制作、人工检查反馈、修改、复查及最终交付的总时间，第一版完成不算目标完成，收到反馈后不重新计时。每组数量变化时重新估算；修改轮次、人工等待和休眠空档都计入总时间。

新的设计预算：0—55分钟完成准备、首套确认、剩余制作及自动检查；55—60分钟展示完整预览并集中收齐用户反馈；60—80分钟定向修改并复查；80—90分钟本地完整性核对与交付（只有另行明确代上传时才安排云端核对）。前30分钟集中决策偏好仍保留，但最终人工反馈是否需要用户短暂返回须在启动确认单说明，不默认用户30分钟以后仍在线。若只在前30分钟参与，只能提前收取首套反馈，不能宣称已取得后续完整成品的人工反馈。

此预算是待验证的工程目标，不是当前已经达成的速度：本批集中出图约63分钟，上传记录扣除112分钟空档后的跨度仍约21分钟，尚未包含全部准备及返工。因此不能仅消除休眠或缩短提示词就宣称90分钟含修改达标。必须实际减少部分AI重生成/版式返工并验证上传提速；现有固定资产及技术检查脚本本身不等于已经实现自动印花合成。生成全量第一版若预计超过55分钟，应尽早报告该预算无法容纳后续修改，并继续已授权工作，不把错误图跳过或缩减范围凑时长。修改超过20分钟时同样记录实际超时，不能停止已授权的必要修正并声称完成。
在批次进度中记录本地时区的任务开始时间、每阶段开始/结束、每次等待用户的起止及原因、生成/修正/上传的实际完成数和耗时。总耗时始终从任务开始计算。启动、首套提交、首套放行、每组完成和上传完成时更新；有工具执行记录时优先使用实际调用时间，文件保存时间只能标为估算。

前30分钟窗口尚有关键决策未完成，或按实测速率预测总计超过90分钟时，报告超时原因和剩余项，继续已获授权的工作；时间目标不自动授权降分辨率、减张数、变更产品、跳过审核或省略云端核对。

## 本机执行防休眠

2026-11-16实测：上传记录18:15—20:07有约112分钟空档，macOS日志显示期间睡眠，20:06:40开盖唤醒后恢复记录。自动睡眠会中断本机工具链；锁屏不等于睡眠。启动确认单提醒用户接电、保持开盖、Codex运行；不承诺合盖或关机后本地流程继续。

正式开始已授权的本地作业时，用临时防休眠，不更改永久电源设置：

```sh
python3 <skill-dir>/scripts/awake_guard.py start --state <local-work>/awake-state.json --seconds 7200
```

状态检查用相同state参数及status；任务完成、等待首套审核并结束当前轮、用户明确暂停/取消或本轮作业异常结束时执行stop。实际继续作业时重新start。只管理该脚本本轮登记的进程；不终止其他防休眠程序。最长默认两小时自动失效，接近失效且任务仍在运行时根据剩余工作重新评估，不能声称永久生效。state为本地工作记录，不上传。仅修改技能或提供建议时不启动守护。

该守护仅防空闲自动休眠，允许屏幕熄灭及锁屏，不能保证合盖、手动睡眠、关机或系统更新时继续。不得把睡眠期间误记为模型或网络耗时。若脚本受环境限制无法启动，报告未生效，不因此跳过当前可执行工作。

## 本地完成制作与修改，用户手动上传（2026-11-17最新选择）

默认在已确认的本地品种目录完成制作、检查和反馈修改，保留稳定编号和同名成品；提供本地路径、数量及预览后完成交付。用户自行上传，不自动上传、不索要网盘目录或上传许可，不将未上传记为失败、待办或阻塞。本节覆盖此前按组上传或最终统一上传的默认规则。

读取或下载已授权的网盘素材仍可进行；复用未变更缓存，核对来源及完整性，不擅自移动或覆盖独立源图。首套审核及必要放行要求继续适用，不因本地交付省略审核。

只有用户后续明确要求代上传时，才按指定目标和范围上传最终选定PNG；核对数量与版本，已成功且哈希未变的不重复上传。不默认上传预览、字体、缓存、诊断文件或ZIP。该例外不恢复以后批次的自动上传默认值。

## 问答确认的批次执行方式（2026-11-16最新）

用户已明确：同一批为同一种产品、多个宠物品种；产品、尺寸及适用底图一次确认，各组复用。不同批次的产品与需求可变化，每批重新取得当次素材及配置，不预先固定未来目录，不把优化问答当成实际开工。

首轮审核选择完整12张，不以3张代表图代替。12张为本轮讨论配置；未来批次如另选模块数量，按当批完整首套审核，不强加12张。首套及必要修改得到明确放行后再继续其他品种。

用户最后选择A（覆盖此前紧接的B答复）：单张同类问题连续两次定向修复仍失败，保留问题图并标为待处理，继续不受影响的已授权图片，最终集中展示问题及可选处理方式，不暂停整批等待。失败图不计完成、不作为定稿上传；已确认且适用的替代修复方法可依既有授权使用，不无限重复相同修复。

继续执行已确认的原图局部换宠物规则，以及本地完成制作与修改、由用户手动上传的方式。总耗时目标仍包含人工反馈、修改、复查与交付，未实测达标前不承诺90分钟完成任意数量。
